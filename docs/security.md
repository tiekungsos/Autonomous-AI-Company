# Security

- **Authentication**: Archon's web authentication (Better Auth; requires PostgreSQL `DATABASE_URL` + `BETTER_AUTH_SECRET`, signup via `ARCHON_AUTH_ALLOWED_EMAILS`) gates every `/api/*` route, company routes included, and the console. Roles (`archon user role`) provide operator/user authorization. Without it, bind to loopback (`HOST=127.0.0.1`, the default here) or put a trusted proxy in front (`ARCHON_WEB_AUTH_HEADER`).
- **Project isolation**: each project has its own repository and origin under `$ARCHON_HOME/company/projects/<id>/`, its own Archon codebase, worktrees, run artifacts, budget and task graph. Staging stacks use a compose project name per project and bind to 127.0.0.1 only. One project never receives another project's paths in prompts.
- **Agent execution isolation**: Devin runs with `--sandbox` (macOS seatbelt / Linux bwrap+seccomp): writes confined to the worktree. Archon worktrees separate checkouts (not a security sandbox by themselves). Claude nodes can add Archon's `sandbox:` option. The Docker socket is never mounted into agent processes; `docker compose` is invoked by a deterministic script node on the host, not by an agent shell.
- **Secrets**: the company layer stores no credentials; engines use their native logins (`devin auth`, `claude login`) or Archon's encrypted per-user keys. Logs carry no credential values (Archon withholds plugin stderr; the plugin logs only metadata). `.env` files are git-ignored.
- **Untrusted input**: requirements, uploaded documents and repository content are quoted as data in prompts (`<requirements>` blocks, "untrusted input"); nothing parses model prose as instructions; verdicts are typed outputs validated by schema, and real exit codes decide validation.
- **Limits**: concurrency caps, per-task retries, per-project repair cap, per-project budget, stale-execution detection, run cancellation on project cancel.
- **Audit**: `company_events` (every decision), Archon's workflow event log and provider events per run, git history on the integration branch (merge commits name the task), transcripts under `$ARCHON_HOME/workspaces`.
- **Production**: no production deployment path exists; staging only, local, loopback-bound. Adding production needs a separately configured, authorized workflow.
